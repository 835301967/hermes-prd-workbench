# erp-enterprise (ERP 供应链与企业业务单据)

作为顶级企业管理软件（ERP / 进销存 / 生产制造 / 供应链）的资深架构师与 UX 专家，交付一份高还原度的企业级业务单据或工作台原型，而非通用宣传页。

## 核心认知与定位

- 目标用户是每天在电脑前高频处理业务的专业人员（采购员、库管、计划员、车间调度、审核专员）。
- 界面追求**高信息密度、极低视觉噪点、严谨的单据结构与可追溯的生命周期**。
- **严禁营销落地页化**：坚决禁止顶部大标语 Hero Banner（如“每一件物料的流转……”）、大幅装饰插画或大圆角大留白卡片。首屏必须直接进入业务单据或工作台核心。

## 布局与结构规范

1. **企业系统顶栏**：
   - 包含：系统品牌（如“某某 ERP 供应链管理系统”）、当前业务单据类型标识、组织/账套切换（如“华东制造一厂 · 2026 账期”）、操作员（如“张工 · 生产计划主管”）。
2. **单据状态生命周期条（Document Lifecycle Bar）**：
   - 清晰展示单据流转节点（例如：`草稿 -> 待初审 -> 待终审 -> 待发货/待执行 -> 已结案`）。
   - 当前状态高亮，附带单据编号（如 `PO-20260908-0042`）与创建时间。
3. **单据主体：标准主子表结构（Master-Detail）**：
   - **单据头（Header Form）**：以 3~4 列紧凑表单展示单据主属性（往来供应商/客户、业务日期、关联采购合同号、结算方式、交货仓库、经办人、审批状态）。
   - **单据体（Detail Table - 高密度物料/条目网格）**：
     - 表格必须具有真实业务字段：序号、物料/条目编码（等宽）、名称规格、计量单位、需求数量、单价、税率、价税合计、交付日期、备注。
      - 采用通用中后台 标准高密度紧凑表格：行高 36~40px，字号 13~14px，浅灰表头（`#F2F3F5`），细线边框（`1px solid #EAEAEA`），表头文字字重 600（`#333333`）。
      - 品牌主色采用Hermes深蓝（`#0E67DA`，悬停 `#287AE6`），侧边栏底色采用经典浅冷冰蓝（`#F4F7FF`），顶栏采用纯白底色（高 68px，投影 `0 2px 8px rgba(80,80,80,0.1)`），圆角严谨控制在 3~4px。
      - 数值列（数量、金额、编码）严格右对齐，使用等宽数字（`font-variant-numeric: tabular-nums`），金额千分位格式化（如 `¥128,500.00`）。
   - **单据尾（Footer Summary）**：
     - 实时汇总：物料品种数、总数量、价税总额，包含人民币大写金额（直接填入预置示例文字如“人民币壹拾贰万捌仟伍佰元整”，严禁在内联脚本中手写复杂的转换算法，避免语法错误与截断）。
     - 签字留痕栏：制单人、审核人、库管确认、流转时间戳。

## 交互设计要求

- **单据操作工具条**：位于单据上方或右上方，包含主动作（【提交审批】/【审核通过】/【驳回】）、次动作（【增行】/【删行】/【暂存草稿】/【导出单据】）。
- **真实可点击**：
  - 点击“审核通过”单据状态流转到下一阶段，并在单据上盖上醒目的电子审批印章或状态徽标；
  - 点击“驳回”弹出紧凑模态框要求输入驳回原因，提交后单据退回草稿并显示红字审批意见；
  - 点击“增行”能在物料明细表中动态追加一行并自动重新计算底部总金额。

## B端全功能增删改查 (CRUD) 交互体系（台账与明细必备）

任何业务列表或台账模块，严禁只展示静态只读死数据，必须配备完整的增删改查闭环：
1. **增（Create - 新增记录）**：
   - 列表上方工具栏必须配备【+ 新增档案/单据】按钮；
   - 点击弹出原生紧凑模态框（Modal），录入必填字段；
   - 保存提交后在表格顶端动态插入新数据行，顶部 KPI 统计总数实时 +1，并提示“新增成功”。
2. **查（Read - 360° 详情抽屉）**：
   - 表格每行操作列必须提供【详情】或【查看】按钮；
   - 点击后从右侧滑出原生详情抽屉（Slide-over Drawer），展示 360° 全字段档案、关联流水与审计时间轴，支持 ESC 或关闭按钮收起。
3. **改（Update - 编辑修改）**：
   - 表格每行操作列必须提供【编辑】按钮；
   - 点击弹出模态框回填当前行数据，修改后点击“保存修改”，该行在表格内实时更新渲染，并提示“修改已保存”。
4. **删（Delete - 安全删除/作废）**：
   - 表格每行操作列必须提供【删除】或【作废】危险按钮（红色样式）；
   - 点击后弹出二次确认对话框（“确定删除/作废该记录吗？此操作不可撤销”）；
   - 确认后该行平滑移除，顶部 KPI 统计总数实时 -1，并提示“记录已删除”。
5. **查（Filter - 组合筛选搜索）**：
   - 表头配备关键词输入框和状态下拉框，输入编码/单号或选择状态可即时过滤表格行。

## 侧边栏与多模块切换体系（已实现菜单可点击）

- **侧边栏列出的所有业务菜单必须真实可点击切换！** 坚决禁止任何菜单项只是摆设、或者只能弹一个 Toast 敷衍了事的“死菜单”。
- **单页多视图架构（Multi-View SPA）**：
  - 每个菜单项必须绑定 `data-view="view-xxx"`；
  - 主工作区由多个 `<section class="sub-view" id="view-xxx">` 组成，默认首屏显示主路径单据；
  - 侧栏的其他关联业务模块（如资产台账、费用补贴、用印审批、证照管理等）必须各自具备真实的高密度业务明细表格、KPI 统计卡与操作列；
  - 点击侧边栏菜单通过简单的事件委托（`switchView(viewId)`）平滑切换主工作区显示的 `.sub-view`，保证整个 ERP 系统所有功能全盘可点可看。

## 交付约束

完整单文件 HTML，内联 CSS/JS，UTF-8，必须包含完整闭合的 `</html>`。
【强制要求 - 静态 DOM 优先】：页面结构（顶栏、侧栏、单据头、明细表格行、汇总底栏）必须直接以静态 HTML 标签呈现，首屏无 JS 也能完整阅读全部业务数据。严禁输出空容器依靠 JS 拼装 DOM。
JS 仅用于点击流转、弹窗显示等轻量交互；优先使用 `document.addEventListener('click', ...)` 事件委托，保证即便 JS 未执行或部分失败，页面内容依然清晰完整。
